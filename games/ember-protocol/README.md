# Ember Protocol

一款支持房间链接联机的浏览器肉鸽游戏。

## 在线游玩

部署完成后访问：

<https://panxie45-coder.github.io/>

创建房间后，把游戏生成的房间链接发给朋友，对方打开链接即可加入。

## 0.16.0 更新

- 建立统一的首发强度预算：坦克/控制机甲靠近预算下沿，玻璃大炮靠近上沿；新增回归测试会阻止后续新机甲以明显超标的基础数值上线。

- BOSS 核心掉落和拾取提示现在会直接显示遗物稀有度；多人模式仍由房主统一决定遗物并同步给全队。

## 0.13.5 更新

- 彻底修复房主倒地后，升级或补给暂停时间超过队友输入超时阈值，恢复战斗时误删队友对象并触发全队结算的问题。

## 0.13.4 更新

- 修复房主倒地时，存活队友完成升级后被旧权威血量帧覆盖并立即死亡的问题；联机升级现在由双方各自选择，待房主确认两边完成后再统一恢复战斗。
- 升级阶段加入存活快照保护：升级开始时存活的玩家不会因同步竞态变成 0 血，已经倒地的玩家也不能借生命上限强化绕过施救直接复活。

- 补给金币由线性击杀奖励改为递减增长结算；击杀越多仍会增加金币，但后期兽潮不再制造数百、数千金币的暴涨。

## 0.13.3 更新

- 删除“每次至少一项本职业强化”的保底机制；四个选项现在统一从通用、本职业与终极奖池按稀有度随机抽取，刷新同样不再保底。
- 再次放慢升级节奏：等级需求采用更陡的成长曲线，并根据当前等级与波次动态压缩经验收益，后期兽潮数量增加时不会继续等比例放大升级速度；强敌仍然比基础敌人提供更多经验。

- 维修包标签会显示剩余秒数；满血玩家仍然不会误捡维修包。

## 0.13.2 更新

## 新机甲内容规范

后续增加任何新机甲时，必须作为完整职业套装交付：

- 机甲主体延续现有写实硬表面、透明背景、俯视战斗机甲风格，轮廓和主色必须与已有职业明显区分。
- 同步制作该职业的专属无人机、普通弹丸、两个小技能特效和终极大招特效，子弹必须从对应机甲或无人机的实际位置发射。
- 同步加入独立碰撞半径、基础属性、至少两个独立小技能、被动技能、终极大招，以及至少三项只属于该职业的特异升级路线。
- 两个小技能都必须拥有可实际改变战斗参数的专属强化；机制强化达到上限后移出奖池，伤害强化允许继续叠加。
- 联机协议必须同步新职业的战斗状态；经验与波次共享，个人升级、金币消费和终极能量保持独立。

## 新敌人内容规范

- 新增远程敌人时，必须同时交付敌人本体、攻击逻辑和独立弹丸/导弹模型。
- 新增近战敌人时，不强行配备导弹；必须同步交付专属挥砍、冲击、突进或碰撞轨迹，并使用贴身伤害判定。
- 新增 BOSS 时，必须提供独立本体模型、阶段机制和与攻击方式相符的弹丸或近战特效，不能直接复用普通敌人的圆点弹丸。
